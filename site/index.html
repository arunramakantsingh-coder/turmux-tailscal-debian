Android Development Appliance

Custom Termux core + Tailscale userspace + Debian • Model 1 • v0.5.0-alpha.7

One APK → automatic provisioning

The separate Provisioner POC has been replaced. This APK is the appliance itself, built from the official Termux v0.118.3 source with the upstream Termux session lifecycle preserved; provisioning is injected only after the normal first session is created.

Download Appliance APK

Fresh-phone flow

  1. Download the APK.
  2. Approve Android's installation prompt.
  3. Open Android Development Appliance.
  4. The first terminal session launches the provisioning flow. For this alpha.7 test build, the Tailscale auth key is supplied at build time through a GitHub Actions secret; the APK does not require a manual key-entry step.
  5. Termux packages, Tailscale userspace, Debian, SSH, proxy support and the local operations page are configured automatically.
  6. Tailscale uses the test credential supplied to the build. Browser/QR authentication is not used in the normal provisioning path.

After provisioning

Run appliance-status or open http://127.0.0.1:8080.

SSH: Termux 8022 • Debian 2222 • SOCKS5 1055.

Manual recovery

curl -fsSL https://raw.githubusercontent.com/arunramakantsingh-coder/turmux-tailscal-debian/main/bootstrap/install.sh | bash
Android boundary: stock Android still requires user approval for sideloading an APK. After that approval, this appliance performs the Termux/bootstrap phase itself. No ADB and no external RUN_COMMAND companion app are used.

Security

The Tailscale auth key is not stored in source control or the Pages site. GitHub Actions receives it as an encrypted Actions secret during the alpha.7 test build. Because this test build embeds the credential into the APK, treat the APK as sensitive and rotate/revoke the test key after validation.
